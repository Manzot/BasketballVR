# BasketballVR

A VR basketball shooting game for Meta Quest 2.

**Unity 6000.0.58f2** | URP | OpenXR | Android (Quest) + PCVR over Quest Link

---

## The constraint that shaped the project

The brief forbids interaction packages that handle grabbing or movement, so **XR Interaction Toolkit and Meta Interaction SDK are not used**. Every piece of interaction - hand tracking, grabbing, holding, throw velocity, haptics, aiming - is written from scratch in this repo.

Packages used, and why each is allowed:

| Package | Purpose |
|---|---|
| `com.unity.xr.openxr` | Headset and controller poses, button state, haptics. Raw device input only. |
| `com.unity.xr.management` | Loads OpenXR at startup. |
| `com.unity.inputsystem` | `TrackedPoseDriver` and XR input bindings. |
| `com.unity.render-pipelines.universal` | Rendering. |
| TextMeshPro | Score and feedback text. |

No package in this project implements grabbing, throwing or locomotion.

---

## Controls

| Input | Action |
|---|---|
| **Index trigger** | Force grab. Point at a ball and pull - it flies to your hand and is caught automatically. |
| **Middle-finger grip** | Close grab. Picks up a ball only when it is already at your hand, so dribbling works. |
| **Release either button** | Throw. Velocity comes from your hand motion, not from the button. |

A thin pointer line runs from each hand. It turns green when a ball is targeted, so what you see always matches what a trigger pull would grab.

## Scoring

Points reward a clean shot rather than any shot:

- A ball must pass the **upper zone above the rim first**, then the **lower zone below it**, while moving downward. Ordering is what rejects a flat throw passing beside the hoop.
- `BasketBall` counts how many surfaces the ball has touched since it last left the ground. Touching the floor resets the count, so every flight is judged on its own.
- Score is `MaxScore` for a clean pass, divided down by bounces: `MaxScore / (bounces * BouncePenalty)`.
- Values live in `GameConstants` - MaxScore 100, MinScore 20, BouncePenalty 2.
- Feedback tiers off the awarded score: **Perfect** (clean), **Great**, **Nice**, each with its own colour, sound and VFX.

## Running it

### In the editor over Quest Link (fastest iteration)

1. Switch to the **Windows** build profile.
2. Project Settings - XR Plug-in Management - **PC, Mac & Linux Standalone** tab: OpenXR ticked, Initialize XR on Startup ticked, and **Oculus Touch Controller Profile** added under OpenXR. Interaction profiles are per-platform tab, and OpenXR will not start a session without one.
3. Meta Quest Link app - Settings - General - set Meta Quest Link as the active **OpenXR runtime**.
4. Open `Assets/Scenes/Court.unity`, connect the headset over Link, press Play.

### On device

1. Switch to the **Android** build profile.
2. Enable Developer Mode on the headset and connect over USB (Air Link does not carry adb).
3. Build And Run.

```
    XR/XRRigSetup.cs       Forces the Floor tracking origin

      HandPointer.cs       In-headset aim line
      BallRack.cs          Spawns the starting balls
      BasketBall.cs        Bounce counting
      ScoreTopZoneValidator.cs / ScoreTrigger.cs   Two-zone score detection
    Events/                ScriptableObject GameEvent / IntGameEvent pattern
    UI/
      ScoreUI.cs           Listens to the score event
      WowEffects.cs        Floating text, VFX and sound per score tier
      MenuUI.cs            Restart and quit
  Art/Models/Hoop.fbx      Rim and net, modelled in Blender via script
```

The court and rig are generated by **editor scripts** rather than hand-placed. Deleting and regenerating gives an identical scene, which made iterating on dimensions cheap and keeps the setup reproducible.

## Design decisions worth knowing

**The rig is hand-built.** Camera and hands are plain GameObjects with `TrackedPoseDriver`. Hands take **position from the grip pose and rotation from the pointer pose** - grip is where your palm is, pointer is where you are aiming, and they are different points on the controller.

**Held balls are driven by velocity, not parenting.** Each physics step the ball's velocity is set toward the hand. A parented ball stops colliding and passes through the rim and floor, which reads as cheap immediately.

**Release velocity comes from a pose history buffer**, not the last frame. The hand's recent poses are averaged so a single noisy frame cannot define the throw. Wrist flick is added from angular velocity.

**Force grab arcs the ball to your hand** rather than teleporting it. The launch velocity is solved so the ball lands at the hand in a set time under normal gravity, then auto-catches on arrival.

**The rim is one mesh, not many colliders.** The first version built the ring from 16 capsules, which made a single rim contact register as several bounces. It was replaced by a single torus modelled in Blender, so one hit is one collision event.

**Ball physics is tuned for readable flight**: Continuous Dynamic collision (a fast ball would otherwise pass straight through the rim), Interpolate (72Hz display against 50Hz physics judders otherwise), and low linear damping so the arc does not stall.

## Known issues and what I would do next

- **Throw velocity is sensitive to frame timing.** Release velocity is derived from per-frame samples, so variable frame time over Air Link adds noise to both speed and direction. The fix is to measure displacement over a fixed time window instead of per frame.
- **Minimum API level is 24** and should be 32 for Quest.
- **No throw assist.** Shipped VR basketball games nudge a near-miss release toward a scoring arc. It is deliberate that this build throws honestly, but assist would raise the make rate and the fun.
- Sound effects are triggered per score tier only; no rim clank, bounce or net audio yet.
